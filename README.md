# 鬼ごっこサークルの参加者ページ

立命館OIC 鬼ごっこサークル（Instagram [@onigo12345](https://www.instagram.com/onigo12345/)）が、公園に置いたQRコードから開くWebページです。アプリのインストールは不要です。

※このサークルは、立命館大学の公認団体ではなく、学生有志によるサークルです。

- 参加者ページ：https://onigo12345.github.io/onigo_participation/
- 集めているデータ（参加者向けの説明）：https://onigo12345.github.io/onigo_participation/privacy.html

このリポジトリは、サークルが**何を集め、どう扱っているか**を誰でも確かめられるように公開しています。データの扱いはすべて [`supabase.sql`](supabase.sql) に書かれたとおりで、それ以外の場所でデータを集めることはありません。

## 参加の流れ

「遊んでから記録する」が基本です。来た時は1タップだけ、記録やアンケートは帰る時にまとめます。

1. **来た時のQR**（赤）を読む → 今遊んでいる人数と「途中参加歓迎」が出る（開いただけでは何も記録しない）
2. 「参加する（18歳以上・注意書きに同意）」を1回押す → 参加番号と来た時刻を記録 →「楽しんできてね！」→「近くの人と一緒に鬼やルールを決めてね！」
   - 18歳未満の人はQRを使わず「入れて」で参加（記録なし）
3. **帰る時のQR**（青）を読む → 今日あそんだ時間と通算の回数（来た時のQRがない日は「未記録」）
4. 「今日タッチした手」を撮る → ストーリー画像を受け取る（シェア・保存。「ふんわり」「強くぼかす」も選べる）。Instagramで使ってよいかもここで選ぶ
5. 任意のアンケート（1問ずつ）：初めての人だけ学部・ニックネームなど → 今日なにして遊んだ → 楽しかった度
6. つぎの鬼ごっこの案内（日にちは決めず、よく開かれる曜日と時間帯を表示）。ここから「わたしの記録を消す」もできる

**開催はゲリラ式**です。開催キー（人ごとに発行）を持つ人が「開始QR」を読んで、公園の写真を1枚撮ると開催が始まり、写真に「鬼ごっこサークル活動中！誰でもこの指とーまれ！」を入れてストーリーに自動で投稿します。終わる時は「終了QR」を読みます（読み忘れても日付が変わると終わる）。終了のあと、開催した人は「今日どんな遊びをしたか」（遊びの種類・ルールや工夫のメモ）を記録でき、管理ページの「開催の記録」に並びます。開いた人が、その回の場の責任者です。開催中でない時は、来た時のページに「本日は未開催」と出ます。

Instagramには、18歳以上の人が「使ってよい」を選び、運営者が管理ページで1枚ずつ承認した画像だけを投稿します。公園の掲示用ページ（`now.html`）には、開始時刻と今の人数が自動で出ます。

QRには設置した人ごとの短い合言葉（`?k=…`）が入っていて、どのQRから来たかがわかります。設置した人の名前はURLに出ません。

## プライバシーの設計

| 方針 | どうしているか |
|---|---|
| 必要なものだけ集める | 本名・学籍番号・連絡先・位置情報・顔写真・端末の情報は集めない |
| 同じ人の見分け | ブラウザの中で作ったランダムな文字列を、サーバーでは SHA-256 にして保存。管理者にも見えない |
| 同じ名前の重複 | 同じ学部・同じニックネームの人がいたら「前にも来た？」と確認。今日すでに参加済みの人にはつなぎ直さない（なりすまし対策）。確認は1端末15回まで（総当たり対策） |
| 参加者からは見えない | 参加者のブラウザは表を直接読み書きできず、決められた処理（`join_visit` など）だけを呼べる |
| 管理者だけが見る | 管理者のメールアドレスでログインした人だけが、記録と画像を見られる |
| 画像 | 非公開の保存場所に置く。写真は作り直すので撮影場所などの情報は残らない。指紋が読み取れるほどの解像度にしない（長い辺1000px） |
| Instagramへの投稿 | 18歳以上の人だけが、受け取りの画面で「ストーリーに載せる」「投稿にも使ってよい」を選べる。運営者が管理ページで1枚ずつ承認すると、ストーリーに投稿（24時間に最大30件）し、フィードの順番待ちに入る。フィードは承認済みの手を参加番号の小さい順に3人ずつ並べ、3枚で1列・糸の柄がつながる形で自動投稿。Instagramの鍵はSupabaseのSecretsにだけ置き、このリポジトリや参加者のブラウザには置かない（[`supabase/functions/instagram`](supabase/functions/instagram/index.ts)） |
| 消せる | 参加者が自分で全部消せる。来場の記録は2年で自動で消える |
| ほかの会社に送らない | フォント・ライブラリ・手の検出モデルは同梱し、外部の配信サービスに接続しない（[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)） |
| 手の検出はスマホの中 | 手の位置の検出は参加者のブラウザの中で行う。写真を外に送って解析することはない |

残っている課題：
- 毎回わざと違う名前を入れる人までは見分けられない（本名などを集めない以上、意図的なもの）
- 参加者のブラウザからは誰でも記録の処理を呼べるため、大量に呼ばれると記録が汚れる可能性がある
- Supabase と GitHub Pages は、通信の記録として IP アドレスを一時的に残す

| `index.html` | 来た時のページ（今の人数・1タップで参加） |
| `bye.html` / `bye.js` | 帰る時のページ（遊んだ時間・撮影と画像づくり・アンケート・次回の日時・記録を消す） |
| `now.html` | 公園の掲示用ページ（開催中か・開始時刻・今の人数を自動で更新） |
| `host.html` | 開催キーのページ（開始QR・終了QR） |
| `visit.js` | 来場の記録（来た時・帰る時で共通） |

| `admin.html` | 管理ページ（画像・来場データ・QRづくり） |
| `supabase.sql` | データの入れ物と、読み書きのルールのすべて |

## 自分で動かす

1. このリポジトリをコピー（fork）し、GitHub Pages を有効にする（Settings → Pages → main / root）
2. [Supabase](https://supabase.com) でプロジェクトを作り、`supabase.sql` のいちばん下のメールアドレスを書き換えて SQL Editor で実行
3. Authentication → Users で、同じメールアドレスの管理者ユーザーを作る
4. `config.js` に Project URL と Publishable key（anon key）を書く。**service_role / Secret key は絶対に書かない**
5. 管理ページ（`/admin.html`）の「QRをつくる」で、来た時・帰る時のQRを作る

`supabase.sql` は何度実行してもデータは消えません。更新した時は、もう一度実行してください。
