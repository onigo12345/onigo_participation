# 鬼ごっこサークルの参加者アプリ

QRコードから開くスマホ用Webアプリです。

1. 「参加してくれてありがとう！ あなたは◯人目の参加者です！」を表示
2. カメラが起動し、画面中央の手形ガイドに合わせて手を撮影
3. 手を自動で検出し、**手と輪郭の周りだけ実写**で切り抜き、赤・青の背景と文字を自動生成
4. Instagramなどへシェア／保存
5. 最初の画面の注意書き（広報に使うことがある旨）に同意して撮影した人の手を、選んだ見え方のまま広報用素材として保存

## ファイル

| ファイル | 役割 |
|---|---|
| `index.html` | 画面（ようこそ＋注意書き・カメラ・生成中・完成） |
| `app.js` | 人数カウント、カメラ、手の検出と合成、見え方フィルター、シェア、広報用素材の保存 |
| `config.js` | Supabaseの接続先、Instagramアカウント名、場所 |
| `supabase.sql` | 人数カウント・画像保存・管理者の設定 |
| `admin.html` | 管理ページ（画像の一覧・来場データ・QRづくり） |
| `bye.html` | 帰る時のQRで開くページ（今日あそんだ時間を表示） |
| `visit.js` | 来場の記録（来た時・帰る時で共通） |

## まず試す（お試しモード）

`config.js` が空のままでも動きます。人数はそのスマホの中だけで数え、画像はどこにも送られません。

カメラはHTTPSでしか動かないので、試すときも下の「公開」をしてからスマホで開いてください。

## 公開する（GitHub Pages・無料）

1. GitHubで新しいリポジトリを作り、このフォルダの4ファイルをアップロード
2. Settings → Pages → Branch を `main` / `(root)` にして Save
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます
4. このURLからQRコードを作る（URLを教えてもらえれば、ポスター用のQR画像も作ります）

## 本番にする（Supabase・無料枠）

全員で通し番号を共有し、広報用の手の素材を集めるために使います。

1. https://supabase.com でプロジェクトを作成
2. SQL Editor に `supabase.sql` を貼って Run
3. Project Settings → API の **Project URL** と **anon public key** を `config.js` に貼る
4. 広報用の手の素材は Storage の `hands` バケットに、記録は `submissions` テーブルに溜まります（どちらも非公開。ダッシュボードから管理者だけが見られます）。素材は、本人が最後に選んだ見え方で、シェア・保存・撮りなおし・画面を離れた時（または20秒操作がない時）に送られます。同じ番号の素材が複数ある時は、一番新しいものが本人の選んだ見え方です（`submissions.look` に none／soft／blur が入ります）
5. `supabase.sql` は何度実行しても大丈夫です。表を作り直した時もそのまま再実行してください

## 来た時のQR・帰る時のQR

QRは「来た時」と「帰る時」の2枚1組です。どちらも、設置した人ごとの短い合言葉（`?k=…`）が入っていて、誰が置いたQRから来たかがわかります。設置者の名前はURLに出ません。

- **来た時のQR**：`/?k=合言葉` → 来場を記録 → 初めての人だけアンケート（学部・ニックネーム・回生・知ったきっかけ）→ 手の撮影
- **帰る時のQR**：`/bye.html?k=合言葉` → 帰った時刻を記録 → 「今日あそんだ時間」と「通算◯回目」を表示 → 楽しかった度（任意・タップだけ）

常連メンバーにQRの設置を任せる時は、管理ページの「QRをつくる」で、その人用のQRの組を作って渡してください。止めたい時は「止める」を押すと、そのQRから来た記録は設置者なしになります。

### 集めるデータ

| 種類 | 内容 | なぜ必要か |
|---|---|---|
| 参加者 | 学部・ニックネーム（本名不可）・回生（任意）・知ったきっかけ（任意） | どの学部・学年に届いているか、どの宣伝が効いているか |
| 来場 | 日付・来た時刻・帰った時刻・設置者（QR） | 開催の時間帯・滞在時間・同時に何人いたか・誰の開催に人が集まるか |
| 来場 | 何回目か・初参加か | リピート率（定着しているか） |
| 来場 | 画像を作ったか・シェアしたか | ストーリーからの広がり |
| 来場 | 楽しかった度（任意） | 開催の満足度 |

**集めないもの**：本名・学籍番号・連絡先・位置情報・顔写真・端末の情報。スマホの見分けには、そのスマホの中で作ったランダムな文字列だけを使います。参加者のスマホからは表を直接読めず、決められた処理（来場・アンケート・帰る）だけができます。

管理ページの「来場データ」で、開催ごとの記録（来場数・初参加・最初に来た／最後に帰った時刻・平均滞在・最大同時人数・画像・シェア・楽しさ）、学部・回生・きっかけ・時間帯の内訳、設置者ごとの集計を見られます。CSVでも保存できます。

## 画像はどこに入るか

| 画像 | 保存先 | 誰が見られるか |
|---|---|---|
| ストーリー画像（1080×1920） | 参加者のスマホ ＋ Supabase の `hands` バケット（`◯◯◯_…_story.jpg`） | 参加者本人／管理者 |
| 広報用の手の素材（透明PNG） | Supabase の `hands` バケット（`◯◯◯_…png`） | 管理者のみ |
| 参加番号・アンケート・来場・作った記録 | Supabase の `participants`・`visits`・`spots`・`submissions` テーブル | 管理者のみ |
| 公式投稿の模様・投稿済みの列 | 公式投稿メーカー（Claude上のページ）の保存領域 | あなたのみ |
| 公式投稿の画像（1080×1440） | メーカーから保存したあなたの端末 ＋ メーカーの保存領域 | あなたのみ |

Supabase のプロジェクトはあなたのアカウントで作るので、参加者アプリの画像と記録はすべてあなたが管理できます。

## 管理ページ（admin.html）

1. `supabase.sql` のいちばん下の `your-email@example.com` を、あなたのメールアドレスに書き換えて実行
2. Supabase の Authentication → Users → Add user で、同じメールアドレスとパスワードのユーザーを作る（Auto Confirm にチェック）
3. 公開したURLの末尾に `/admin.html` をつけて開き、ログイン

できること：参加者数の確認／1人ずつ最新の画像（本人が選んだ見え方）を一覧／見え方で絞り込み／手の素材・ストーリー画像を1枚ずつ、またはまとめて（zip）保存／「掲載をやめてほしい」と連絡が来た番号の画像と記録をまとめて削除。

公式投稿メーカーには、ここでまとめて保存した手の素材（PNG）を入れてください。

## 仕組みのメモ

- **手の検出**：Google の MediaPipe Hand Landmarker（ブラウザ内で処理）。外部に送るのは、本番モードで保存する広報用の手の素材（手と周りの余白だけ）のみです
- **実写の範囲**：検出した手の骨格から、指・手のひら・腕の形を余白つきで塗り、その範囲だけ写真を残します。余白は `app.js` の `MARGIN`（手のひら長さ×0.12）で調整
- **背景**：赤と青の円が重なり、重なった部分が紫になる形で全員共通
- **文字**：見出しは「つかまえた。」、下に「◯人目のおともだち」「つぎは君も、このゆびとーまれ！」、右下にアカウント・日付・場所
- **番号**：同じスマホで開き直しても同じ番号のまま（端末に記録）。通信に失敗した時は仮の番号を残さず、撮影時にもう一度取りにいきます
- **画像処理**：iPhoneのSafariは canvas のぼかし・明るさ調整（filter）が効かないため、ぼかしと色調整は自前の処理で行っています。撮影した写真は手のまわりだけを切り出してから処理するので、古い機種でも重くなりにくくしています

## 注意

- InstagramやLINEの中のブラウザではカメラが起動しないことがあります。その時は自動で「カメラアプリで撮る」に切り替わります。QRは標準カメラアプリで読むのがおすすめです
- 「シェア」はiPhoneのSafari、AndroidのChromeで使えます。非対応の端末では「保存してから投稿してね」と案内します
- 最初の画面の注意書き（取り下げ方法など）は、サークルの運用に合わせて `index.html` を書き換えてください。掲載をやめてほしいと連絡が来たら、Storage と `submissions` から該当番号の素材を削除してください
- 画面を開いてすぐ参加番号が「?」になる時は、Supabaseの設定（URL・キー・SQLの実行）を確認してください。ブラウザの開発者ツールのコンソールに理由が出ます
- 参加番号は、端末の記録（ブラウザのデータ）を消すと新しい番号になります。厳密な人数ではなく「来てくれた端末の数」として扱ってください
